01

全体像 — 表示状態と非同期操作をつなぐ

ViewModelは、画面が見る状態とRepositoryが持つ永続データの間を調整します。

View操作・表示
一覧 / エラー
↔
ContentViewModel表示状態・操作台帳
楽観更新・再取得調整
→
ReminderRepositoryEventKitとの読み書き
ReminderStoreCache初回表示・一覧の保存
Repositoryの変更通知　↶　remindersMayHaveChanged → loadReminders()
画面状態

editableLists が基準

リストとリマインダーを保持。reminders はその配列を平坦化した読み取り用プロパティです。

調整

操作をUUIDで追跡

取得・保存・完了更新・削除を reminderOperations に登録し、完了時に取り除きます。

目的

古い結果で巻き戻さない

変更中の再取得を抑え、必要ならすべての変更後に最新状態を一度だけ読み直します。

02

状態と操作台帳

見た目の状態、進行中操作、後で行う処理をそれぞれ別に持ちます。

状態役割読み方のポイント
editableLists表示対象のリストと各リマインダーキャッシュまたはRepositoryの取得結果が入る。操作によっては即時に楽観更新される。
reminderOperations操作IDをキーとするTaskの辞書OrderedDictionary<UUID, ReminderOperation> で追加順を保持する。UUIDは辞書のキーで管理し、完了時に removeValue(forKey:) で対応する操作だけを取り除く。
pendingCompletionUpdatesデバウンス待ちの完了状態リマインダーIDごとに最後に選ばれたBoolを保持し、連続操作をまとめる。
shouldReloadAfterMutation変更完了後の再取得予約更新中に通知や失敗で必要になった読み直しを、全変更操作の終了まで保留する。
completionToggleLockedReminderIDs保存中の完了切り替えロック同じIDの保存が終わるまで、連続した新しい切り替えを受け付けない。
isLoading

.load が台帳にある間はtrue。Repositoryが実際に動作中かだけでなく、Repository内の待機中も含みます。

errorBinding

Viewのアラート表示と error を結び、アラートを閉じる操作でエラーをnilに戻します。

03

一覧取得 — キャッシュを先に、最新値を後に

起動直後の表示速度と、Repository由来の正確な状態を両立します。

① 競合確認変更中なら再取得を予約
›
② 古い取得を取消前の結果による上書きを防止
›
③ Repository取得を開始async letで非同期に起動
›
④ 初回キャッシュを並行読込あれば最新取得より先に表示
›
⑤ 最新結果で更新キャンセル確認後に一覧とcacheへ反映
i
初回キャッシュは「仮の表示」です。
キャッシュが読めてもRepositoryの取得は続き、最新結果で置き換えてからキャッシュを更新します。キャッシュの有効期限は24時間で、読めなくても処理を続けます。

取得Taskの終了時にはdeferで操作台帳から削除します。キャンセルされた取得はエラー表示されません。lastAppliedRepositoryFetchID はキャッシュではなく、Repositoryの結果を反映したときだけ更新され、画面側が選択中リストなどを再検証する合図になります。

04

作成・編集 — 変更分だけ保存する

入力フォームの確定をTaskとして追跡し、編集では差分のみRepositoryへ渡します。

作成

作成先リストを解決

listIdentifier が現在の編集可能なリストに見つからない場合、内部の ContentViewModelError.reminderDestinationListUnavailable を ReminderEditorError.destinationListUnavailable に変換してフォームへ返します。見つかったリストと入力内容をRepositoryへ渡します。

編集

変更がない項目はnil

タイトル・優先度は元の値と比べ、変更時だけ値を渡します。期限はフォームの deadlineUpdate を利用し、編集時に元の所属リストを変更しません。

// notesは「維持 / 消去 / 設定」の3状態をRepositoryへ伝える let notes: String?? = if draft.notes == (reminder.notes ?? "") { nil // 変更しない } else { .some(draft.notes.isEmpty ? nil : draft.notes) // 空なら消去 }

保存Taskは Result を返し、呼び出し元のフォームにエラーを返します。成功時は成功の触覚フィードバック、キャンセル以外の失敗時は失敗の触覚フィードバックを発生させます。

05

完了状態 — 楽観更新とデバウンス

タップの反応をすぐ画面に出しつつ、Repositoryへの保存をまとめます。

1
即時に表示更新displayedIsCompletedを反転。削除予定や保存中の対象は無視。
2
変更をIDごとに記録最後に選択された完了状態をpending辞書に置く。
3
待ち時間をリセット追加のタップごとにデバウンスTaskを再予約。
4
まとめて保存各IDについてsetを実行。成功したら確定状態も更新。
元の値に戻った

表示状態が保存済み状態と一致したらpendingから削除。無駄な保存をしません。

画面が非アクティブ

ScenePhaseがactive以外になったとき、待ち時間を待たずに保留中の更新を保存へ回します。

!
連続切り替えの重複を防ぐ
保存中のリマインダーIDはロックされ、同じ項目への追加タップは無視します。削除が始まると、そのIDの保留中・実行中の完了更新をキャンセルします。
06

削除 — 表示を先に無効化する

削除中の再操作と、削除前の古い取得結果による復活を防ぎます。

① 削除予定にする行の重複削除を防止
›
② 関連処理を止める完了更新と一覧取得を取消
›
③ Repositoryで削除操作Taskを台帳で追跡
›
④ 成否を反映成功なら行を除去、失敗ならエラー
›
⑤ 必要なら再取得通知や失敗後に最新状態を読み直す

削除成功時は画面上の項目を先に取り除きます。失敗時はエラーを表示し、変更操作がすべて終わってから再取得する予約を立てます。

07

競合の調整 — 再取得は変更が落ち着いてから

操作途中のスナップショットが楽観更新やキャッシュを巻き戻さないようにします。

i
変更中にfetchを始めない
loadReminders() は変更中なら予約フラグだけを立てます。各変更Taskのdeferが台帳から自身を外し、最後の変更が終わった時点で予約があれば一度だけ再取得します。

Repository変更通知も同じルールです。エラー表示中は通知からの自動再取得を抑え、利用者がエラーを確認・回復する操作を待ちます。

08

エラーとViewModelの破棄

キャンセルは通常の失敗表示にせず、権限失効は専用の回復処理に渡します。

権限失効
  • 再取得予約を解除
  • デバウンス・保留更新を破棄
  • 台帳のTaskをすべて取消
  • 権限失効ハンドラーを実行
キャンセル
  • CancellationErrorとRepositoryのcancelledを検出
  • 画面エラーに変換しない
  • 古い取得結果を適用しない
通常エラー
  • 一覧・完了・削除は用途別のContentViewModelError
  • 入力エラーはReminderEditorError
  • 保存失敗をフォームへthrow
通知監視

初期化時にRepositoryの変更通知を購読。エラー表示中は無視し、変更操作中は再取得予約、それ以外はすぐ取得します。

deinit

通知監視を解除し、デバウンスTaskと管理中Taskをキャンセルします。破棄後は結果を画面に反映できないため、作成・更新が完了しない可能性を許容する設計です。

09

読むときの短いまとめ

コードを追うときは、画面更新とRepository反映を別々のタイミングとして見るのがコツです。

取得

キャッシュは初回の先行表示

その後Repositoryの結果が正となり、画面とcacheを更新。

完了

即時表示、遅延保存

IDごとに最後の状態だけを一定時間後にまとめて保存。

変更中

再取得要求を保留

変更操作の最後が終わるまで待ち、必要なら一度だけ再取得。

寿命

破棄時はTaskも停止

画面がなくなった後に状態更新を続けない。
